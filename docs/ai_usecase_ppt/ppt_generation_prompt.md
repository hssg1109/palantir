## Gemini NotebookLM 용 프롬프트

```
첨부된 문서는 AI/LLM을 실제 보안 진단 업무에 적용한 사례 발표자료 원고입니다.

이 내용을 바탕으로 사내 AI 활용 사례 공유 세션용 PPT 슬라이드 구성안을 만들어주세요.

[요구사항]
- 슬라이드 수: 16~18장
- 청중: 보안 비전문가 포함한 사내 직원 전체
- 톤: 전문적이되 어렵지 않게, 실제 수치와 사례 중심
- 각 슬라이드마다: 제목 / 핵심 메시지 1줄 / 본문 내용(불릿 3~5개) / 발표자 노트

[슬라이드 구조]
1. 표지: "AI로 보안 진단을 자동화한 이야기"
2. 목차
3. 배경: 왜 AI가 필요했나 (기존 한계)
4. 무엇을 했나: AI 적용 3대 영역
5~6. Before: 수동 방식의 한계 (구체적 수치 + `$` 검색으로 후보를 찾은 뒤 역추적이 필요한 간접 주입 경로 사례)
7~8. After: AI 적용 후 변화 (Before/After 표 포함)
9. 실제 수치: 1,931건 → 248건, 31개 레포, 3주 완료 (단계별 의미가 분명한 퍼널로 표시)
10~11. 산출물 소개: 자동 생성 보고서, Audit Log, Memory로 자동 축적되는 진단 기준
12~14. 재사용 프롬프트 6종(번호 없이 이름으로 통일, 3개 그룹): [탐지정확도] 역추적형 교차검증 / 컨텍스트별 XSS 판정 — [판정근거] 시크릿 진위 판별 / CVE 판단 — [산출물자동화] 기준 문서화 / 보고서 작성. 각 항목은 "실제 사례 → 사용한 문구 → 결과" 3단 구성으로 통일
15. 진단 기준 자기 갱신 (Audit 피드백 루프)
16. 한계와 주의사항 (솔직하게 — 대형 레포 timeout 실제 사례 포함)
17~18. 마무리: AI 전환으로 얻은 성과와 기대효과 (한계에서 이어받지 않음)

[디자인 가이드]
- 배경: 다크 네이비 또는 딥 블루 계열 
- 강조색: 시안(#00B4D8) 또는 라임 그린
- 코드/JSON 예시는 코드 블록으로 표시
- Before/After는 좌우 2분할 레이아웃
- 수치는 크게 강조 (폰트 크기 업)
```

## Claude 용 프롬프트

```
아래에 첨부한 문서는 AI/LLM을 보안 진단 업무에 실제 적용한 사례 발표자료 원고입니다.

이 내용을 바탕으로 PPT 슬라이드 스크립트를 작성해주세요.

[출력 형식]
각 슬라이드를 아래 형식으로 작성:

## 슬라이드 N: [제목]
**핵심 메시지**: (한 줄 요약)
**본문**:
- 불릿 1
- 불릿 2
- 불릿 3
**발표자 노트**: (말할 내용 2~3문장)
**시각 요소 제안**: (그래프, 표, 아이콘 등)

---

[주요 강조 포인트]
1. 수치로 말하기: 1,931건 → 248건, 31개 레포 3주, 오탐 27.4%
2. 역할 변화가 핵심: "탐색 → 판정"으로 담당자 역할 전환
3. 재사용성: 청중이 내일 바로 써먹을 수 있는 프롬프트 6종을 3개 그룹(탐지정확도/판정근거/
   산출물자동화)으로 소개, 번호 없이 이름으로 통일. 각각 "실제 사례 → 실제 사용한 문구 →
   그 문구로 얻어낸 결과" 순서로 제시해 기법과 결과의 인과관계를 분명히 보여준다
4. 구체적 사례로 신뢰도 확보: `$` 검색으로 찾은 Mapper 후보를 Controller까지
   역추적해야 했던 SQL Injection 사례, API 4,176개 레포 timeout 등 실제 겪은 상황을
   예시로 포함
5. 솔직함: AI의 한계도 포함하되, 마무리는 한계가 아니라 성과·기대효과로 끝맺는다

[슬라이드 수]: 16~18장
[청중 수준]: 보안 전문가부터 비전문가까지 혼재
[발표 시간]: 20~25분
```

## 핵심 수치 레퍼런스 (슬라이드에 활용)

| 수치 | 의미 |
|---|---|
| **31개** | 진단 완료 레포 수 (OCB 서비스군) |
| **1,931건** | AI 스캐너가 탐지한 전체 후보 |
| **248건** | 최종 확정 Finding (LLM 교차검증 후) |
| **87%** | AI가 자동 처리한 비율 (1,931 중 1,683건은 양호/필터) |
| **27.4%** | 오탐률 (스캐너 후보 중 실제 취약이 아닌 비율) |
| **5개** | AI 판정 피드백이 공식 진단 기준으로 확정된 사례 수 |
| **2~4시간** | AI 도입 후 레포 1개 진단 소요 시간 |
| **5분** | 보고서 초안 자동 생성 시간 |
| **3주** | 31개 레포 전체 진단 완료 소요 시간 |

## 슬라이드 핵심 스토리라인

```
[문제 제기]
  → 31개 레포를 수동으로 하면 몇 달. 현실적으로 불가능

[해결책 소개]
  → AI가 1,931건을 스캔하고, 사람은 248건만 판정

[증거]
  → Before/After 수치, 실제 보고서 화면, Audit Log 예시

[재사용]
  → 이 6가지 프롬프트(문구+결과)만 있으면 누구나 내일부터 시작 가능

[솔직한 한계]
  → AI는 실행 환경을 모른다. 최종 판단은 항상 사람이

[마무리 — 한계에서 이어받지 않고 성과로 마무리]
  → 3주 완료, 기준 자산화(Memory), 재사용 가능한 워크플로 확보
  → AI가 판단의 상당 부분을 수행하고, 사람은 최종 확인·승인에 집중하는 구조
```

## 이미지/시각화 아이디어

| 슬라이드 | 시각 요소 |
|---|---|
| Before/After | 좌(빨강): 수동 흐름도 / 우(초록): AI 자동화 흐름도 |
| 수치 | 2단 퍼널(각 단계 수치·비율 라벨 명시): "AI 스캔 후보 1,931건" → "LLM 정밀검토 316건(정탐248+오탐68)" → "최종 확정 248건". 막대 폭만으로 의미를 전달하지 말고 단계마다 무엇을 세는 수치인지 텍스트로 병기 |
| 역할 변화 | 가로 스택 막대 비교(기존 vs 현재, 도넛 대신) + 하단에 근거 캡션: "AI가 1,931건 스캔·분석 → 사람은 최종 248건 판정 + 13건 위험도 조정에만 관여(약 13.5%)" — 수치 슬라이드와 근거를 직접 연결 |
| 피드백 루프 | 순환 화살표 다이어그램: 판정→누적→기준→자동적용→판정 |
| grep 누락 사례 | Mapper(XML, `$` 검색으로 발견)→Service→Controller 역방향 3단 박스 흐름도, 발견 지점(Mapper)과 확인 대상(Controller) 강조 표시 |
| 프롬프트 | 6개 모두 동일한 3단 구성(실제 사례 / 사용한 문구 / 결과)으로 통일, "문구"는 인용구 스타일로 짧게, "결과"는 구체적 수치·산출물로 명시 |
| 대형 레포 timeout | Before(4,176 endpoints 단일 스캔, timeout 표시) / After(모듈 800~1,000개씩 분리, 체크 표시) |
| 한계 | 경고 아이콘과 함께 5가지 한계 나열 |
