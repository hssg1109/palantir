# 회의 자료(초안) — Repo 종료 기록 / 담당자 매핑

## 현황(배경)

기존 원천데이터(`system_code_to_repo` JSON, CMDB 스냅샷)가 아래 2가지로 불충분해
"DB 기준" 논의(티켓 동기화 방식 / DB 변경 절차 / 공통 메타데이터 최소화)는 시기상조로 판단, 보류.
지금 정리 가능한 아래 2개 안건으로 압축.

- 다중 시스템 매핑 레포 존재 (152건)
- AWS 서비스 등 목록에서 제외되어 있음

## 회의에서 정리해야 할 내용

**회의주제1 — 종료 repo에 대한 기록 논의**
- 종료 판단 기준
  - 담당자/PM 확인, 공식 서비스 종료 공지
  - 서버 비활성화, Repo archived/deleted
  - → 무엇을 확정 기준으로 보고, 무엇을 참고 신호로 볼지 결정
- 라벨링 문구 (어떤 표기로 통일할지)
- 어디에 기록할지 (`ocb_scan_plan.md` 체크리스트 / `repo_config.json` / 별도 레지스트리)

**회의주제2 — repo 별 담당자 매핑**
- 어디에 기록할지 (현재 `palantir-jira-gateway/data/repo_config.json`에 51개 레포만 수작업 존재)
- 유지 방식 (수작업 지속 / 주기적 일괄 갱신 / Jira 연동 자동화)
