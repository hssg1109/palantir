01

개요

보안진단 결과를 Jira SECUFINDINGS 프로젝트에 직접 발급하기 위한 연동 규격입니다. Jira Server/DC REST API v2를 사용하며, PAT(Personal Access Token) Bearer 인증 방식을 따릅니다.

이 규격은 팔란티어 게이트웨이를 경유하지 않고, 외부 시스템이 Jira에 직접 이슈를 생성하는 방법을 정의합니다. 토큰은 보안진단 담당팀에서 발급하여 제공합니다.
외부 시스템 우선순위 페이지 / 취약점 목록
→
Jira REST API POST /rest/api/2/issue
→
SECUFINDINGS 티켓 담당자 배정 · PDF 첨부
02

인증

Jira Server/DC 환경이므로 PAT Bearer 방식을 사용합니다. 모든 요청에 아래 헤더를 포함해야 합니다.

헤더값비고
Authorization Bearer <JIRA_PAT> 보안진단팀에서 발급한 PAT. 절대 코드에 하드코딩 금지 — 환경변수로 관리
Content-Type application/json 이슈 생성·조회 모든 요청에 필수
X-Atlassian-Token no-check 파일 첨부(multipart) 요청에만 필요. 일반 JSON 요청에는 불필요 
# curl 예시
curl -s -X POST \
  "https://jira.skplanet.com/rest/api/2/issue" \
  -H "Authorization: Bearer $JIRA_PAT" \
  -H "Content-Type: application/json" \
  -d @payload.json
03

이슈 생성 API

이슈 생성

POST https://jira.skplanet.com/rest/api/2/issue

요청 본문(JSON)에 fields 객체를 포함하여 전송합니다. 성공 시 201 Created와 함께 생성된 이슈 키가 반환됩니다.

이슈 조회 (중복 확인용)

GET https://jira.skplanet.com/rest/api/2/search?jql=project%3D%22SECUFINDINGS%22+AND+labels%3D%22{repo}%22&maxResults=1

동일 레포 티켓이 이미 존재하는지 사전 확인 시 사용합니다. total > 0이면 기존 티켓이 있습니다.

파일 첨부 (선택)

POST https://jira.skplanet.com/rest/api/2/issue/{issueKey}/attachments

이슈 키를 받은 후 multipart/form-data로 파일을 첨부합니다. X-Atlassian-Token: no-check 헤더가 필요합니다.

04

필드 레퍼런스

fields 객체에 포함할 수 있는 전체 필드 목록입니다. FIXED는 고정값, REQUIRED는 필수, OPTIONAL은 선택 필드입니다.

API 필드 키필수값 / 형식설명
project.key FIXED "SECUFINDINGS" 타깃 Jira 프로젝트 키. 변경 불가
issuetype.name FIXED "Task" 이슈 유형. 보안진단 티켓은 Task로 고정
priority.name FIXED "Major" 우선순위. Major로 고정
reporter.name FIXED "pc10315" 보고자. 보안진단 담당자로 고정
summary REQUIRED string (최대 255자) 티켓 제목. 예: "[보안진단] ocb-event-front 취약점 조치 요청"
description REQUIRED Jira Wiki markup 티켓 본문. Markdown이 아닌 Jira 위키 마크업 사용 (§5 참고)
labels REQUIRED string[] (공백 불가) 레포명 + 프로젝트 키 배열. 예: ["ocb-event-front", "OCBWEBVIEW"]
assignee.name OPTIONAL string (Jira username) 담당자 Jira 계정명. 미지정 시 Unassigned
customfield_21500 OPTIONAL "YYYY-MM-DD" 조치기한 커스텀 필드. 날짜 형식 엄수

05

필드 매핑 가이드

외부 시스템(priority/view)의 데이터를 Jira 필드에 매핑하는 기준입니다. 페이지에서 제공되는 실제 항목명에 맞게 조정하여 구현하세요.

Jira 필드권장 매핑 소스변환 규칙
summary 취약점 제목 / 서비스명 + 진단 유형 예: "[보안진단] {서비스명} 취약점 조치 요청"
labels 레포명, Bitbucket 프로젝트 키 레포명은 공백 없이 그대로, 프로젝트 키는 대문자. 배열로 전달
assignee.name 서비스 담당자 Jira 계정명 Jira Server/DC는 name(계정명) 사용. email 아님
customfield_21500 조치 기한 YYYY-MM-DD 형식으로 변환 필수
description 진단 결과 본문 전체 Jira Wiki markup 형식 변환 필요 (Markdown 직접 사용 불가)
담당자 계정명 확인 방법
GET https://jira.skplanet.com/rest/api/2/user/search?username={검색어}
응답의 name 필드가 assignee.name에 사용할 값입니다. (email X)

07

응답 및 오류

성공 응답

// HTTP 201 Created
{
  "id":   "123456",
  "key":  "SECUFINDINGS-2200",
  "self": "https://jira.skplanet.com/rest/api/2/issue/123456"
}

반환된 key로 티켓 URL을 구성합니다: https://jira.skplanet.com/browse/{key}

주요 오류 코드

HTTP원인해결 방법
401 PAT 누락 또는 만료 Authorization 헤더 및 토큰 유효성 확인
400 필드 형식 오류 (날짜, 필수 필드 누락 등) 응답 본문의 errors 객체에서 문제 필드 확인
400 assignee 배정 불가 (프로젝트 권한 없음) 보안진단팀에 해당 계정의 Users role 추가 요청
403 이슈 생성 권한 없음 PAT 발급 계정의 프로젝트 권한 확인

담당자 배정 가능 여부 사전 확인

GET https://jira.skplanet.com/rest/api/2/user/assignable/search?project=SECUFINDINGS&username={username}

응답 배열이 비어있으면 해당 계정은 SECUFINDINGS에 배정 불가. 보안진단팀에 권한 추가를 요청해야 합니다.
